# 战策每轮架构合规检查清单（强制执行，每轮第一项）

> **生效时间**：2026-09-08
> **执行要求**：战策每轮开发前，必须先完成本清单的所有检查项，并将结果记录在DEVLOG的"架构合规检查"章节中。未完成本清单不得开始开发。
> **监控审核**：监控任务每轮必须检查本清单的完成情况，发现未完成或违规立即要求战策修正。

---

## 一、本轮开发前必须完成的检查（按顺序）

### 1.1 读取架构红线文档
- [ ] 已读取 `docs/ARCHITECTURE_BOUNDARY.md`
- [ ] 已确认本轮要开发的功能属于"战策可以做的"范围
- [ ] 已确认本轮不会开发"战策禁止做的"功能

### 1.2 检查Ember SDK有没有现成能力
- [ ] 已读取 `D:\Sojourn\ember\dist\sdk\SDK_README.md`
- [ ] 已读取 `D:\Sojourn\ember\dist\sdk\sdk-manifest.json`
- [ ] 已确认本轮功能是否需要Ember SDK能力
  - 如果需要：Ember SDK有现成能力 → 必须使用SDK
  - 如果需要：Ember SDK没有 → 记录`[SDK需求]`，提给Ember任务，不自己实现
  - 如果不需要：跳过

### 1.3 检查Arboreus SDK有没有现成能力
- [ ] 已读取 `D:\Sojourn\arboreus\docs\SDK.md`
- [ ] 已读取 `D:\Sojourn\arboreus\docs\SDK_API.md`
- [ ] 已确认本轮功能是否需要Arboreus SDK能力
  - 如果需要：Arboreus SDK有现成能力 → 必须使用SDK
  - 如果需要：Arboreus SDK没有 → 记录`[SDK需求]`，提给Arboreus任务，不自己实现
  - 如果不需要：跳过

### 1.4 越界实现检查
- [ ] 已检查本轮要修改/新增的代码是否属于"禁止做的"范围
- [ ] 已确认不会新增灵魂数据/行为/AI决策/世界模拟/物理碰撞/路径寻路/事件系统等越界实现
- [ ] 如果必须临时实现（SDK确实没有且阻塞开发）：已记录临时替代方案，并承诺SDK上线后立即替换

---

## 二、本轮开发中必须遵守的规则

1. **只做应用层**：UI、交互、玩法规则、关卡设计、美术表现、音效、游戏流程
2. **不碰核心层**：灵魂数据、灵魂行为、AI决策、世界模拟、物理碰撞、路径寻路、事件系统、经济系统
3. **SDK优先**：基础功能先查SDK，没有的提需求，不自己造轮子
4. **临时实现必须标记**：代码中临时实现的越界功能必须加`// TODO: 临时实现，待SDK能力上线后替换`注释
5. **完整测试**：必须测试完整游戏流程，不只是单元测试

## 四、违规处理

1. **监控发现战策未完成本清单**：立即在监控报告中指出，要求战策下一轮先补做
2. **监控发现战策有越界实现**：立即要求战策下一轮回退或替换，严重情况可暂停战策任务
3. **连续两轮违规**：监控必须更新战策任务prompt，强化架构约束
4. **用户确认违规严重**：可降低战策任务频率，优先完成架构梳理和SDK集成

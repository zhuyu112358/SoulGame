# 战策架构红线（最高优先级，不可违反）

> **生效时间**：2026-09-08
> **制定原因**：战策当前过度自由发挥，自己实现了世界构建和灵魂行为，导致与Ember/Arboreus引擎能力脱节，项目有失控风险。
> **执行要求**：战策每轮开发前必须阅读本文档，严格遵守职责边界。违反架构红线的实现必须立即回退或替换。

---

## 一、核心原则

**战策 = 应用层 + 玩法层 + 表现层**

战策只负责"游戏怎么玩、怎么呈现"，**不负责"灵魂是什么、世界怎么运转"**。

灵魂和世界的核心能力**完全依赖Ember和Arboreus引擎SDK**，战策只调用，不重新实现。

## 四、SDK缺失时的正确流程

当战策需要某个能力但SDK没有时，**绝对不能自己临时实现**，必须按以下流程：

1. **确认需求**：明确需要什么能力、输入输出、性能要求
2. **检查SDK**：仔细阅读Ember SDK_README和Arboreus SDK_API.md，确认确实没有
3. **提需求**：在战策DEVLOG中记录`[SDK需求]`，写明：
   - 需要的能力名称和描述
   - 期望的API接口
   - 优先级（P0阻塞/P1重要/P2优化）
   - 临时替代方案（如果有）
4. **监控转发**：监控任务每轮收集战策的SDK需求，同步给对应引擎任务
5. **引擎开发**：Ember/Arboreus任务按优先级开发SDK能力
6. **战策接入**：SDK能力上线后，战策立即接入，删除临时替代方案

**临时替代方案只能作为过渡，不能成为永久实现。** 监控任务会跟踪每个SDK需求的状态，确保最终被引擎能力替代。

## 五、当前战策越界实现清单（必须逐步替换）

以下是战策当前自己实现、但按架构红线应该依赖引擎的模块。战策必须在后续轮次中逐步替换为SDK调用。

| 模块 | 当前实现位置 | 应依赖 | 优先级 |
|------|------------|--------|--------|
| SoulAIController | scripts/game/SoulAIController.gd | Ember 感知-决策-行动 | P1 |
| SoulUnit（灵魂数据/行为） | scripts/game/SoulUnit.gd | Ember 灵魂数据+行为 | P1 |
| RTSArenaManager（世界状态） | scripts/game/RTSArenaManager.gd | Arboreus 世界模拟 | P2 |
| ArenaMap（碰撞/空间） | scripts/game/ArenaMap.gd | Arboreus 物理/空间 | P2 |
| EventBus（事件系统） | scripts/autoload/EventBus.gd | Arboreus 事件总线 | P2 |
| GameState（状态管理） | scripts/autoload/GameState.gd | Arboreus 世界状态 | P3 |

**替换策略**：
- 不要求一次性全部替换，按优先级逐步进行
- 每替换一个模块，必须完整测试确保功能正常
- 替换过程中保留旧实现作为降级，SDK调用失败时自动回退
- 每轮DEVLOG必须报告替换进度

## 六、战策每轮工作流程（强制执行）

```
1. 【读设计】读取设计文档和设计符合度反馈，明确本轮目标
2. 【读架构】阅读本文档，确认职责边界
3. 【查SDK】检查Ember/Arboreus SDK是否有现成能力
   - 有 → 必须使用SDK
   - 没有 → 提SDK需求，不自己实现（除非有临时过渡方案且已记录）
4. 【设计架构】设计应用层的代码架构和实现路径
5. 【实现】只实现应用层职责范围内的功能
6. 【完整测试】运行完整游戏流程测试，检查log，定位问题
   - 不只是单元测试，必须测试从主菜单→灵魂选择→战斗→结束的完整流程
   - 必须有完整的log输出，方便跟踪定位
7. 【对齐确认】确认实现符合项目目标和设计要求
8. 【记录】DEVLOG记录：SDK使用情况、SDK需求、越界检查、替换进度
```

## 七、监控审核职责

监控任务每轮必须检查：

1. **越界检查**：战策本轮是否实现了架构红线禁止的功能
2. **SDK使用**：战策是否优先使用SDK，有没有重复造轮子
3. **SDK需求跟踪**：战策提出的SDK需求是否已同步给引擎
4. **替换进度**：越界模块的替换进度
5. **完整测试**：战策是否做了完整运行流程测试，而不只是单元测试

发现违反架构红线的情况，监控必须：
- 立即在报告中指出
- 要求战策下一轮回退或替换
- 严重情况可暂停战策任务直到修正

---

## 八、测试要求（完整流程测试）

战策的测试不能只停留在单元测试层面，必须包含：

1. **完整流程测试**：主菜单→灵魂选择→设置→战斗→战斗结束→返回主菜单
2. **运行时冒烟测试**：启动游戏后检查是否有SCRIPT ERROR、资源加载失败
3. **Log跟踪**：每个关键节点必须有log输出，方便定位问题
4. **视觉渲染测试**：检查单位是否可见、z-index是否正确、UI是否正常
5. **资源完整性检查**：所有引用的资源文件是否存在、是否被正确导入

测试可以由战策自己执行，也可以交给集成测试任务执行。但战策每轮必须至少运行一次完整流程测试。
